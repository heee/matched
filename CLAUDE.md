# Working conventions for this repo

Source of truth for product/screens/copy/mechanics: `docs/Matched_Build_Spec_v1.0.md`.
Pixel-level styling reference: `docs/design-reference.html` (ignore its
`x-dc`/`sc-for`/`sc-if` templating syntax — read it for CSS values,
structure, and copy; its `#1f` board is a working reference implementation
of the game engine and was ported into `game/mahjong.js`).

- **Minimize dialogue.** Keep responses terse — critical messages and summaries only, no play-by-play narration.
- **Deploy without asking.** After committing a fix/feature to `master`, push to `origin master` immediately — don't pause for confirmation first. This is client-only (GitHub Pages auto-deploys from `master`); it does NOT cover `worker/index.js`, which still needs the manual Cloudflare dashboard paste described below.
- **Worker deployment:** no wrangler (Windows ARM64 has no `workerd` build) and no Cloudflare API token in this environment. `worker/index.js` is deployed manually by pasting into the Cloudflare dashboard's Quick Edit — it deliberately has no imports outside itself. Run `npm run validate-worker` before pasting. See `scripts/deploy-worker.cjs` for the full manual checklist (create D1 database, apply `migrations/0001_initial.sql`, bind `DB`/`ROOM`, set `APP_KEY`/`ALLOWED_ORIGIN`).
- Before any preview check: unregister service workers + clear caches, then reload.
- Bump `sw.js`'s `CACHE_NAME` on every shipped change.
- Root scripts are ESM (`package.json` has `"type": "module"`); the CommonJS scripts are `.cjs`.
- **Keep `app.js` as orchestration, not a feature warehouse.** Screens live in `screens/*.js` (each renders into a root container and wires its own events). Game logic — board generation, free-tile detection, matching, scoring, tiers — lives in `game/*.js` as pure functions, no DOM, unit-tested in `tests/`.
- Icon generation uses `@resvg/resvg-js` (see `scripts/generate-icons.cjs`), not `sharp` — `sharp` has no native binary for this machine's win32-arm64 target and its wasm32 fallback failed to load here. Swap back to `sharp` freely on a machine where it installs cleanly; the SVG source (`icons/icon-source.svg`) is unaffected either way.
- **Design-implementation tasks aren't done until verified against the reference, element by element.** Rendering without errors is not the same as matching the design. Before marking any visual task complete: reload the actual page (cache-busted) and check every distinct element named in `docs/design-reference.html` — colors, spacing, order, badges, icons, copy — against that reference directly. Do this per screen as each is finished.
- **For major/new-feature work, ask clarifying questions one-by-one before planning.** Don't guess at ambiguous requirements or batch every open question into one message.
- Board math: tile geometry is 40×52pt face, 40pt column/row step, 5pt offset per layer (`game/layouts.js` `TILE_W/TILE_H/STEP_X/STEP_Y/LAYER_OFFSET`). A tile is free iff nothing sits directly above it and it isn't blocked on both left and right at its own layer (`game/mahjong.js` `isFree`). Boards are generated by reverse construction, which guarantees solvability by construction — see `generateFromPositions`.
- Player identity color (`game/scoring.js` `colorForPlayer`) is identity-first: a player's own stored hue (`PLAYER_HUES`, auto-assigned at registration, user-editable from Profile > Settings, synced to the Worker's `users.hue` column) wins over seat position, so a player reads the same color everywhere and to every other player. Falls back to the fixed 4-color rotation (`PLAYER_COLORS`) by seat order, then an OKLCH hue rotation beyond 4 seats, only for names with no stored hue yet (bots, unsynced remote seats).
